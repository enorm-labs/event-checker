### 🔴 T-1 · Tempodrom stores `&amp;` undecoded in titles, artist names **and slugs** — NEW · ✅ FIXED

> **Fixed** on 2026-08-03. `TempodromOverviewPageScraper` now runs `name` and `description` through a
> `decodeHtml` helper (`Parser.unescapeEntities`, the same call `lark` / `madameclaude` /
> `cosmiccomedy` / `barjedervernunft` use). `Scala & Kolacny Brothers` was added to
> `KNOWN_SINGLE_ACTS`, since decoding newly exposes that `&` to the co-bill splitter and the choir is
> one act. Verified by re-import: 0 entity-bearing titles, 0 `-amp-` slugs, all 142 events still
> stored. The 5 corrupted `artist` rows are now orphaned (0 links) rather than updated in place.

The venue's JSON-LD is HTML-escaped, and `TempodromOverviewPageScraper` reads `name` straight off the node without unescaping. The raw entity then flows into
the event title, into the artist minted from that title, and into both slugs — so it is user-visible *and* baked into the identity keys.

```sql
SELECT e.id, e.title, e.event_date
FROM event e
         JOIN venue v ON v.id = e.venue_id
WHERE e.title ~ '&(amp|#0?39|quot|nbsp|lt|gt|apos);';
```

**Count: 5 events + 5 artist rows** (every `&`-containing title at this venue; no other source is affected).

| id   | title                                    | artist slug                          |
|------|------------------------------------------|--------------------------------------|
| 2159 | `Beisenherz &amp; Polak - Friendly Fire` | `beisenherz-amp-polak-friendly-fire` |
| 2227 | `Eiskönigin 1 &amp; 2`                   | `eiskonigin-1-amp-2`                 |
| 2260 | `Elena Uhlig &amp; Fritz Karl`           | `elena-uhlig-amp-fritz-karl`         |
| 2276 | `Laura Abla &amp; Ceddo`                 | `laura-abla-amp-ceddo`               |
| 2287 | `Scala &amp; Kolacny Brothers`           | `scala-amp-kolacny-brothers`         |

**Root cause:** `TempodromOverviewPageScraper.kt:81-83` — `.path("name")` with no unescape step. The fix already exists in the codebase:
`LarkApiScraper.kt:328` defines `decodeHtml(raw) = Parser.unescapeEntities(raw.trim(), false).trim()`, and `barjedervernunft`, `madameclaude` and `cosmiccomedy`
use the same helper. Tempodrom is the one JSON-reading scraper that skips it.

Note the secondary effect: because the entity survives into the artist name, the `&`-splitter never sees a real `&`, so `Scala & Kolacny Brothers` is stored as
one artist where the co-bill splitter would normally have had a say.

|-----|-----------------------------------|-------------|

### 🟠 T-3 · 118 events store an event *category* in `event.genre` — NEW · ✅ FIXED (scraper half)

> more.

### 🟠 T-5 · Frannz Club's `&`-split cuts inside parentheses, producing `Rockets)` — NEW · ✅ FIXED

> **Fixed** on 2026-08-03, and it was worse than reported: the title produced **three** bogus
> artists, not one — `David J (Bauhaus`, `Love` and `Rockets)` — where the act is `David J`.
> `splitHeadlinerTitle` and `splitSegmentOnConjunctions` are now bracket-aware via a shared
> `isInsideBrackets` guard, so neither a hard separator (`/`, `+`) nor a conjunction is ever cut
> inside a `(…)` / `[…]` group. This is the title-level counterpart of the guard Club der Visionäre's
> lineup parser already had. An unclosed bracket only makes it more conservative, keeping a
> malformed title whole rather than fragmenting it. Verified by re-import: 103/103 Frannz events
> still stored, event #580 now billed to the single act `David J (Bauhaus / Love & Rockets)`, the
> three fragments orphaned, and **0** artists with unbalanced brackets linked anywhere in the
> database.

```sql
SELECT id, name
FROM artist
WHERE name ~ '^[[:punct:]]|[[:punct:]]$';
```

Event #580 `David J (Bauhaus / Love & Rockets)` — a headliner billed with his two former bands — was split on the `&` *inside* the parenthetical, storing artist
#609 as the fragment **`Rockets)`**, complete with the unbalanced bracket.

**Count: 1 artist row**, but the pattern is general: any Frannz Club title with `&` inside a parenthesised affiliation will fragment the same way.

**Root cause:** the shared co-bill splitter runs before/without paren-awareness at this venue. Club der Visionäre explicitly solves this — "acts are split at a
`b2b` marker and at `&`/`and`/`und` boundaries, but **never inside parentheses**" — and Columbia Theater relies on the same protection for
`Budgie (SIOUXSIE & THE BANSHEES, THE SLITS)`, which is stored correctly here (artist #785). Frannz Club is not getting that guard.
